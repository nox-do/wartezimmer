# Wartezimmer 6.1.5

Dieses Sicherheitsrelease aktualisiert die Node-Runtime der App- und
Sandbox-Container auf **22.23.4** und behebt dort die Brotli-Schwachstelle
**CVE-2026-111497**. Präparierte Brotli-Daten können in älteren Runtimes
Speicherfehler bis hin zur Codeausführung auslösen. Die App verarbeitet unter
anderem Antworten externer Nachrichtendienste über `fetch()`.

**Bestehende Installationen sollten das passende `.pfupdate`-Paket einspielen.**
Ein Update von npm-Abhängigkeiten oder des separat installierten Node ersetzt die
Runtime in bereits ausgelieferten Containern nicht.

## Änderungen

- App und Sandbox verwenden Node 22.23.4 mit unveränderlich festgelegtem
  Basis-Image. Auch die Build- und Prüf-Pipelines verwenden diese Node-Version.
- Die ausgelieferten Container erhalten zusätzliche Laufzeithärtung. Nicht
  benötigte npm-/npx-Werkzeuge werden aus den Runtime-Images entfernt.
- Setup validiert Konfigurationswerte strenger und schreibt Änderungen atomar;
  bestehende Dateirechte bleiben erhalten.
- Ausgelieferte Proxy-Konfigurationen verlangen ein ausdrücklich gesetztes,
  geprüftes Proxy-Image, statt unbemerkt auf ein Standard-Image zurückzufallen.
- Die noch offene Manager-Schwachstelle ist mit Risikobewertung und
  Behebungskriterien in `KNOWN_VULNERABILITIES.md` dokumentiert.

## Installation und Update

Die Downloads enthalten Manager für macOS Apple Silicon, macOS Intel und Windows
x64 sowie `.pfinstall`- und `.pfupdate`-Pakete für Linux ARM64 und AMD64.
Updatepakete 6.1.5 unterstützen weiterhin **Manager ab 6.1.3**. Vor dem Update
eine Sicherung erstellen und das Paket passend zur Architektur des Docker-Hosts
wählen. Für eine bestehende Installation `.pfupdate`, für eine Neuinstallation
`.pfinstall` verwenden.

Die Manager-Installer werden weiterhin ohne Herausgebersignatur und ohne
Apple-Notarisierung bereitgestellt. Betriebssystemwarnungen sind daher zu
erwarten. Die Prüfsummen der Downloadpakete stehen in `SHA256SUMS.txt`.

## Bekannte Sicherheitslücke im Manager

**CVE-2026-111497 bleibt in der eingebetteten Runtime des Managers 6.1.5 und dem
darin gestarteten Setup offen.** Electron bleibt auf 44.4.3. Das Node-Update der
Container behebt diese separate Runtime nicht.

Die lokale Setup-API auf `127.0.0.1` reduziert die Exposition. Beim entsprechenden
TLS-Setup kontaktiert das eingebettete Setup jedoch den konfigurierten
ACME-DNS-Server; manipulierte Brotli-Antworten dieses Servers bleiben relevant.
Nur vertrauenswürdige ACME-DNS-Server verwenden.

Die Behebung im Manager ist bis zu einem bestätigten stabilen Electron-Fix
zurückgestellt. Die zum Bewertungszeitpunkt geprüften stabilen Versionen 44.9.3
und 45.0.0 enthalten noch Node 24.22.0; der bestätigte Node-Fix liegt in
24.22.1. Ein Wechsel auf Electron 46 Alpha wird für dieses Release nicht
vorgenommen. Details und Kriterien für die spätere Behebung stehen in
[KNOWN_VULNERABILITIES.md](https://github.com/nox-do/wartezimmer/blob/v6.1.5/KNOWN_VULNERABILITIES.md).

Der Stand der offiziellen Sicherheitsmeldung ist im
[Node-Advisory vom 21. Oktober 2026](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases)
dokumentiert.
