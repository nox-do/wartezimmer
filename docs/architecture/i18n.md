# i18n — Übersetzungsrichtlinie

**Scope:** Welche Oberflächen welche Locales haben; kanonische Listen; Beitragsregeln.  
Nicht: Ops-Persistenz der Locale-Liste → [`domain.md`](domain.md) / Ops-Settings · API-Rollen → [`apis.md`](apis.md)

## 1. Kurzfassung

| Oberfläche             | Sprachen                                          | Mechanismus                             |
| ---------------------- | ------------------------------------------------- | --------------------------------------- |
| Terminal (`/terminal`) | de-DE, en-GB, tr-TR, ru-RU, uk-UA (Ops-gesteuert) | `t()` / `tf()` + Sprachwahl             |
| Portal (`/portal`)     | wie Terminal                                      | gleiche Patienten-Locale (localStorage) |
| MFA, Ops, TV           | **nur de-DE**                                     | Locale erzwingt `STAFF_LOCALE`          |

Neue Staff-Texte → `de-DE.ts`. Patienten-Locales nur Overrides für `terminal` / `portal` (+ minimale `ui`).

## 2. Kanonische Liste

**Single source of truth:** `packages/domain/src/terminal-patient-locales.ts`

- `TERMINAL_PATIENT_LOCALES` / `TerminalPatientLocale`
- `normalizeTerminalPatientLocales` — Ops-Patch/DB; `de-DE` immer enthalten

UI leitet `APP_LOCALES`, `PATIENT_LANGUAGE_OPTIONS`, Tastatur-Layouts daraus ab — keine parallele Liste.

## 3. Locale-Auswahl

`getAppInitialLocale()` in `ui/src/lib/i18n/patient-locale.ts`:

- Patientenpfade (`/terminal`, `/portal`): gespeicherte Terminal-Sprache oder Browser-Fallback
- alle anderen Pfade: immer `de-DE` (`STAFF_LOCALE`)

Wechsel Terminal → MFA: Root-Layout zurück auf Deutsch.

**Ops:** `terminalPatientLocales` unter MFA → Betrieb. Terminal liest die Liste aus dem Heartbeat; Portal aus `GET /api/v1/ops/patient-locales`. `PatientLangPicker` filtert Buttons und fällt bei Deaktivierung auf `de-DE` zurück.

## 4. Locale-Dateien

| Datei                                 | Inhalt                                                          |
| ------------------------------------- | --------------------------------------------------------------- |
| `de-DE.ts`                            | vollständiges Wörterbuch (Staff + Patient); Basis für `AppDict` |
| `en-GB` / `tr-TR` / `ru-RU` / `uk-UA` | `...deDict` + Overrides nur terminal/portal (+ minimale ui)     |

Keine partiellen Ops-/MFA-/Auth-Übersetzungen in Patienten-Locales.

## 5. API (`t` / `tf`)

- Keys: Dot-Notation aus `AppDict` (`TranslationKey`)
- `t(key)` / `tf(key, vars)` — Platzhalter `{name}`
- Bootstrap: Root-`+layout.svelte` → `initI18n(getAppInitialLocale(pathname))`

**Ops Setup-Hints:** Server-Codes → deutsche Konstanten in `setup-check-hints.ts`, nicht `t('ops…')`.

**Terminal-Themen:** Labels aus MFA-Einstellungen (Deutsch); bei en/tr/ru/uk optional Browser-Translator-API (`BrowserTranslatedText.svelte`) — kein eigener i18n-Key pro Thema.

## 6. Regeln für neue Texte und Sprachen

- Staff-Oberfläche → neuer Key nur in `de-DE.ts`
- Patienten-Locales nur `terminal` / `portal` (+ minimale `ui`)
- Neue Sprache: Domain-Liste + Locale-Datei + `PATIENT_LANGUAGE_META` + OpenAPI-Enum + ggf. Tastatur
- Rein deutsche Ops-/IT-Texte: Konstante/Inline, kein `t()`
