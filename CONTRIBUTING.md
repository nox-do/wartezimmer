# Beiträge zu Wartezimmer

Wenn ihr etwas beitragen möchtet, öffnet bitte zuerst ein [GitHub Issue](https://github.com/nox-do/wartezimmer/issues). Beschreibt das Problem oder eure Idee. Stimmt die Änderung bitte mit mir ab, bevor ihr einen Pull Request erstellt.

Für Sicherheitsprobleme gilt der private Meldeweg in [SECURITY.md](SECURITY.md). Öffentliche Issues und Pull Requests dürfen keine Patienteninformationen, Zugangsdaten oder unbereinigten Diagnosepakete enthalten. Beispiele und Tests verwenden fiktive Daten.

## Lizenz und Zustimmung

Für Beiträge gelten die Bedingungen der [Wartezimmer-Lizenz 1.1](LICENSE), insbesondere die Beitragsregelung in Abschnitt 3. Bitte den vollständigen Text vor der Einreichung lesen. Die Abstimmung über eine Änderung ersetzt die dort erforderliche ausdrückliche Zustimmung nicht.

Wenn ihr einen Beitrag zur Übernahme einreicht, erklärt bitte im Pull Request ausdrücklich eure Zustimmung zur Beitragsregelung und bestätigt, dass ihr die erforderlichen Rechte am Beitrag habt. Nennt bei Drittanbieterinhalten die Herkunft und Lizenz. Ich prüfe den Beitrag und entscheide über die Übernahme.

## Prüfung einer Änderung

Im Pull Request das Problem, die Änderung und die durchgeführten Prüfungen beschreiben. Die Entwicklungsanleitung steht in der [README](README.md); `npm run verify` und `npm run build` bilden den allgemeinen technischen Prüfweg. Zusätzliche Integrationsprüfungen richten sich nach der Änderung und werden in einer separaten Testumgebung mit fiktiven Daten ausgeführt.

## Sprache und Ansprache

Texte für Anwender verwenden „Sie“, Texte für Mitwirkende „ihr“. Code-Kommentare,
technische Beschreibungen und Funktionsmeldungen bleiben möglichst neutral.
Persönliche Projektaussagen stehen in der Ich-Form; wo diese unpassend wirkt,
ist eine neutrale Formulierung vorzuziehen. Fragen aus Sicht einer Praxis dürfen
weiterhin „wir“ verwenden. Zitate und historische Gesprächsprotokolle behalten
ihren ursprünglichen Wortlaut.
